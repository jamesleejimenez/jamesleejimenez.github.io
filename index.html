What I do

Three things, and they feed each other.

Evaluate and train language models

I build the environments a model gets tested in, write the criteria it gets scored against, run the model through them, and document exactly where it went wrong. Not a thumbs up or a thumbs down, but a written record another person can act on. Design prompts and the workflows around them

A prompt that works once is a trick. A prompt that works on the tenth try, in someone else's hands, with messy inputs, is a tool. I write prompts with the inputs named, the output shape fixed, and the known failure modes written down underneath, then I test them against cases built to break them.

  • Output schemas
  • Test cases
  • Version control
  • Handoff documentation

Mercor, 2026 to now

Evaluation environments for business and HR scenarios

I own tasks end to end. I build the fictional company a model has to operate inside, write the documents and records it has to reason over, set the task and the answer key, then write the criteria a grader scores against. After that I run models through it, read every step of the run, and write up why each one passed or failed.

The hard part is not writing the task. It is making a task that is difficult for a good reason, where a strong model fails because it skipped a real step, not because the wording was tricky. Every criterion has to point at one sentence in the source material, or it is not a criterion, it is an opinion.

  • Scenario design
  • Answer keys
  • Grading criteria
  • Model comparison
  • Written failure analysis

LLM evaluation toolkit

The rubrics, report templates, and scoring script I use to keep evaluations consistent across runs and across people. It includes scored rubrics for instruction following, factual accuracy, and tone, a worked example comparing two model answers on the same task, and a small Python script that turns a folder of scores into per criterion averages and a reviewer agreement check.
